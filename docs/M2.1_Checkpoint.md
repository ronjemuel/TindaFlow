## Behavior and limits

Startup opens Welcome. Explore demo explicitly enters the original M1 experience
with sample data. Profile is available from the demo banner and More tab. The
original workspace dropdown and cart operations still use DemoStore. The new
switcher lists sample businesses only while in demo, and switching clears the
cart through the existing `switchBusiness` method. It never assigns account roles.

Account forms validate locally, then show account setup required. They never
claim sign-in, registration, email delivery, verification, password reset,
business creation or sign-out succeeded. No backend is connected, no SDK was
added, and no session token, password or live business record is stored. Passwords
are not included in saved instance state. Loading UI represents the account
availability check only, so it may be too brief to observe with this local adapter.

Preview upcoming screens on Welcome exposes all future states for review.
Language selection changes displayed resource strings for the current preview
session only; persistence and Android app-language integration remain future work.
Demo data still has its original in-memory lifecycle. Process death can reset it.
No real deep-link handler or authenticated business data host exists in M2.1.
The future authenticated session type is a routing contract, never instantiated
by these forms. Backend authorization and RLS belong to later milestones.

## Phone and screenshot checklist

Install `app/build/outputs/apk/debug/app-debug.apk` on your phone.

1. Cold start: Welcome shows forest green, ivory, TindaFlow leaf branding, and
   clear preview labeling. Capture a screenshot.
2. Login: submit blank fields and an invalid email. Confirm field errors, email
   keyboard, Next/Done behavior, password masking and visibility accessibility
   labels. Valid input must show setup required and must not open business data.
3. Register: check short password and mismatched confirmation errors. Use only
   disposable test text. Confirm no account or verification email is claimed.
4. Forgot password and its Reset preview: validate fields, confirm no recovery
   email or password update is claimed. Back must return through the prior screen.
5. Welcome → Preview upcoming screens → email verification: check both actions
   report missing setup. Capture Check Inbox and Reset screenshots.
6. Business setup preview: enter a name, select Retail, Services, and Both, check
   optional details and Asia/Manila/PHP defaults. Create must not create a workspace.
   Capture onboarding and the empty live-workspace switcher.
7. Explore demo: visit Dashboard, Sales, New Sale, Inventory, Orders. Confirm the
   approved appearance and existing filters, dialogs, demo checkout/stock updates,
   and original workspace dropdown still work. Capture each screen if comparing.
8. Open Profile from the banner or More. Visit the sample business switcher,
   change business, and return. Products and cart must not cross workspaces.
   Open Profile during New Sale and return without switching: cart and checkout
   UI must remain intact. Leave demo must return to Welcome and clear the cart.
9. Language: select Filipino and English, verify new screens and errors translate
   without changing route. Relaunch is allowed to return to the device language;
   the page explicitly describes session-only selection. Capture both languages.
10. Rotate the phone, open the keyboard, enlarge font/display size, and use TalkBack.
    Scroll every form to its bottom: no controls should clip or hide behind system
    bars/keyboard. Passwords should clear after leaving the form or recreating it.
11. Repeat account submissions in airplane mode. They must still report missing
    setup honestly, with no claimed network request or success.

No device or emulator tests have been performed by Codex. Screenshot comparison,
TalkBack, keyboard/insets, rotation and large-font checks require phone verification.
